# 卡牌包前三阶段审阅汇总

## Phase 1

- 提交：`960797d` `拆分导入校验的错误与警告基础结构`
- 审阅方式：subagent 审阅
- 审阅结论：
  - 高：新增的错误/警告拆分 helper 还没有接入真实导入链路，当前导入流程仍会把所有校验问题当成失败处理，阶段目标尚未真正生效。
  - 中：`.dhcb/.zip` 导入结果新增了 `warnings`，但卡包管理页汇总时没有把这部分信息透传到 UI，后续即使接通宽松导入，归档导入也无法展示警告。
  - 中：新增测试只覆盖了 helper 的分类逻辑，没有覆盖真实导入入口，无法自动验证“结构合法但引用缺失”的卡包是否会成功导入并返回 warnings。
- 处理计划：
  - 在 Phase 2 中把严格/宽松模式正式接入 `store.importCards()`、`_validateImportData()` 和 `.dhcb` 导入路径。
  - 在 Phase 2 中补上导入链路级测试，并把 `.dhcb` warnings 继续透传给页面结果。

## Phase 2

- 提交：`9dfa58a` `接入导入宽松校验模式`
- 审阅方式：subagent 审阅
- 审阅结论：
  - 高：`import_relaxed` 还没有覆盖 `profession[].名称` 这类“职业卡自身缺少批次元数据声明”的场景，导致 profession 卡在没有 `customFieldDefinitions.professions` 时仍会导入失败。
  - 中：页面已经收到了 `.dhcb/.zip` warnings，但卡包管理页当前还没有展示 warnings，用户仍然看不到“成功但有提示”的提醒。
  - 中：新增测试里有一条用例 mock 了 `_validateImportData()`，只能证明 `importCards()` 会转发 warnings，不能覆盖真实宽松校验入口。
- 处理计划：
  - 在 Phase 3 中补上 profession 卡的宽松分类前提，让后续元数据自举可以成立。
  - 在 Phase 3 中新增真实元数据规范化 helper 的单测，并补一条不依赖 mock 的宽松校验覆盖。
  - warnings 的页面展示属于文档中的 Phase 5，本轮前三阶段先继续保留为已透传、未展示。
